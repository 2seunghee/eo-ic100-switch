# attic: 스피커 출력 (빌드하지 않음)

eofm 0.1.3~0.2.0에서 시도하고 0.2.2에서 뺀 "라디오는 이어폰이 잡고, 소리는 본체 스피커로" 기능입니다. 다시 시도할 때 참고하려고 남겨 둡니다.

이어폰의 FM 칩을 녹음 모드(`SET 14 = 1`)로 두면, 라디오 소리가 USB 마이크(IF1, EP 0x83)로 스위치에 들어옵니다. 문제는 그 마이크를 스위치 오디오 모듈(`audio`, 0100000000000014)과 나눠 쓰는 방법이었습니다.

| 버전 | 방법 | 결과 |
|---|---|---|
| 0.1.3~0.1.5 | usbhs-logmitm이 마이크 단자만 고쳐 써서(it_mic) 스위치가 이어폰을 마이크 전용 USB 장치로 인식하게 함. 앱은 audin으로 `Uac_*` 입력을 엶 | 출력은 스피커로 바뀜. 오디오 모듈도 EP 0x83 isoc을 받음. 하지만 앱의 `AppendAudioInBuffer(Auto)`는 모든 크기에서 2153-0008로 거부됨 |
| 0.1.6 | USB 입력 전용 명령 `AppendUacInBuffer(Auto)`(IAudioIn 10/7)를 직접 보냄 | 앱(앨범 애플릿)에서 `svcCreateEvent`가 안 돼 잘못된 핸들이 들어감. **오디오 모듈이 2003-0501로 중단** |
| 0.2.0 (speaker.c) | usbhs-logmitm이 오디오 모듈의 인터페이스 목록에서 이어폰을 지움(hide). 앱이 IF1을 직접 잡고 isoc IN으로 읽음 | 오디오 모듈이 목록 개수를 믿지 않고 비운 칸(ID 0)을 8번 잡으려다 **Data Abort로 중단**, 이어서 홈 메뉴도 중단 |

남은 아이디어(시험할 때마다 콘솔 오류를 감수해야 함):
- 마이크 인터페이스만 오디오 모듈에게 오디오 클래스가 아닌 것으로 보이게 하기. 디스크립터의 IF1 alt들과 목록 항목의 클래스를 0xFF로 바꾸고, 목록에서 지우지는 않음.
- 애플리케이션 모드(타이틀 가로채기)에서 이벤트를 만들 수 있으면, 올바른 핸들로 `AppendUacInBuffer`를 다시 시험하기.
